# 機能仕様: 勤務時間入力（REQ-UC003）

**Branch**: `001-work-time-entry` | **Date**: 2026-11-06

**正本**: [REQ-UC003-勤務時間入力.md](../../attendance-system-workshop-ja-v1.1.1/docs/requirements/REQ-UC003-勤務時間入力.md)

**関連**: [REQ-000](../../attendance-system-workshop-ja-v1.1.1/docs/requirements/REQ-000-System-Requirements-Specification.md) の 4.2.3 と 4.3.1、[E2E](../../attendance-system-workshop-ja-v1.1.1/e2e/features/REQ-UC003-勤務時間入力.feature)

## ユーザーストーリー

従業員として、日々の勤務時間を記録したい。正確な勤怠管理を行うため。

**優先度**: P1

## 受け入れ基準

- 従業員が日付を選択できること
- 従業員が出勤時刻と退勤時刻を入力できること
- システムが従業員 ID、日付、出退勤時刻の必須・形式を検証すること
- 時刻が `HH:MM`（00:00〜23:59）であり、出勤時刻が退勤時刻より前であることを検証すること。同刻・逆転・日跨ぎは許可しない
- 未来日付の入力を許容すること
- 検証に成功した場合、`status=WORK` として勤怠情報を保存すること。保存済みの場合は同じ従業員・日付のレコードを更新し、別レコードを作らない
- 保存後、時刻は秒 `00` を付けた `HH:MM:SS` で取得できること
- 保存時に備考を変更せず、新規レコードでは備考を NULL とすること。作成日時は新規作成時に設定し、更新日時はレコードが更新されたときに更新すること
- 入力エラー時は日本語エラーを表示し、保存せず、ダイアログを開いたままにすること
- 未登録日の初期表示は空欄とする。取得エラーはダイアログに表示し、再読み込みできること
- 保存成功時はダイアログを閉じて成功メッセージを表示し、キャンセル時は保存しないこと

## 機能範囲

- 日付選択（既存のカレンダー操作の結果を使う）
- 出勤時刻・退勤時刻の入力
- 入力値バリデーション
- 保存: `POST /api/attendance`
- 特定日取得: `GET /api/attendance/{employeeId}/{date}`
- 一覧取得: `GET /api/attendance/{employeeId}`
- 一覧取得は既存 API 契約に従い、任意の `startDate` / `endDate` で期間を絞り込める

## API 契約補足

- UC003 の画面は `employeeId`、`attendanceDate`、`clockInTime`、`clockOutTime`、`status=WORK` を送る。保存 API は HTTP 200 と勤怠レコードを返し、成功メッセージは画面側で表示する
- 必須・形式・順序エラーは HTTP 400 と `{error, message, timestamp}` を返す。エラーの優先順は従業員 ID、日付、未入力時刻、時刻形式、出勤・退勤順序とする
- 従業員 ID 形式不正は ERR03004、日付形式不正は ERR03005、時刻未入力は ERR03003、時刻形式不正は ERR03002、時刻順序不正は ERR03001。予期しない API エラーは HTTP 500 / ERR99001
- 特定日取得の未登録は HTTP 404 / ERR02001。画面はこれを未登録として空欄にし、エラー表示しない。その他の取得失敗では入力欄と保存を無効にしてエラーと再読み込み操作を表示する
- 保存失敗時はダイアログを開いたままエラーを表示し、再入力・再送信できる
- 一覧取得では `startDate` と `endDate` は任意で、指定した境界日を含む。日付形式不正は HTTP 400 / ERR03005、逆転範囲は HTTP 200 と空配列を返す。未指定時は当該従業員の全件を返す

## 対象外

- 認証と従業員マスタ。従業員 ID は既存どおり `EMP001`
- 休暇登録（REQ-UC004）の画面・ルール詳細
- カレンダー上の勤怠バッジ表示

## 非機能

- 勤怠データの永続化と、従業員＋日付の一意性による整合
- 利用者に分かる日本語のエラーメッセージ
- 性能目標、負荷試験基準、ページネーション、一覧結果の並び順は UC003 の実装・受入条件に含めない
