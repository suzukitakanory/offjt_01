# クイックスタート: 実装済み勤務時間入力の確認

実装済み UC003 の自動テストと操作を確認する。契約の詳細は [contracts/attendance-uc003.openapi.yaml](./contracts/attendance-uc003.openapi.yaml)、項目規則は [data-model.md](./data-model.md)。

## 前提

- ブランチ `001-work-time-entry`
- 従業員 ID は `EMP001`
- 開発時の API は `http://localhost:8080`、画面は `http://localhost:5173`
- 既存の起動手順は `attendance-system-workshop-ja-v1.1.1` の README に従う

## 1. 自動テスト

プロジェクトの README に従って開発 DB、バックエンド、フロントエンドを起動してから実行する。

```sh
cd attendance-system-workshop-ja-v1.1.1/backend && mvn test
cd ../frontend && pnpm lint && pnpm build
cd ../e2e && pnpm test --tags @REQ-UC003
```

## 2. 操作・API確認

1. メイン画面で日付を選ぶ。
2. 勤務時間入力を開き、09:00 と 18:00 を保存する。成功メッセージが出る。
3. 同じ日付を再び開き、08:30 と 17:30 を保存する。別レコードにならず、時刻が更新される。
4. 18:00 と 09:00 は保存されず、「出勤時刻は退勤時刻より前である必要があります」が出る。
5. 25:00 は保存されず、「有効な時刻形式で入力してください」が出る。
6. 未来日の 09:00〜18:00 は保存される。
7. ダイアログを開くと特定日を取得する。未登録日は API が 404 / ERR02001 を返し、画面はエラー表示せず空欄にする。既存日は `HH:MM` で初期表示する。
8. `GET /api/attendance/EMP001?startDate=2025-01-01&endDate=2025-01-31` は指定期間の勤怠を返す。開始日・終了日は結果に含まれる。開始日が終了日より後なら 200 と空配列になる。
9. 不正な従業員 ID は 400 / ERR03004、不正な日付は 400 / ERR03005 となり、日本語のエラー応答を返す。
10. 取得 API が 404 以外のエラーを返す場合、入力欄と保存は無効になり、エラーと再読み込み操作が表示される。保存 API が失敗した場合はダイアログが開いたままで、エラーを修正して再送信できる。
11. キャンセルでは保存 API を呼ばずにダイアログを閉じる。

E2E の対象シナリオは [e2e/features/REQ-UC003-勤務時間入力.feature](../../attendance-system-workshop-ja-v1.1.1/e2e/features/REQ-UC003-勤務時間入力.feature)。一覧範囲はバックエンド単体・コントローラーテストで検証する。性能試験、一覧の並び順、ページネーションは実装・受入条件に含まれない。
