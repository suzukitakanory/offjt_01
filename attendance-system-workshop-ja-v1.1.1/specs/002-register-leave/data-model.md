# Data Model: 休暇登録

休暇は独立したテーブルを持たない。既存の日次勤怠レコードのうち、休暇ステータスを持つものを休暇レコードとして扱う。物理定義の正本は `offjt_01/attendance-system-workshop-ja-v1.1.1/docs/design/database-table-definitions.md` である。

## 従業員

勤怠システムを利用できる本人。この機能ではサーバー設定のデモ従業員1人だけを対象にする。

- 識別子: 従業員 ID。既定値は `EMP001`。
- 関係: 自分の休暇レコードだけを登録、取得、変更、削除できる。
- 対象外: 管理者による代理登録、承認、他の従業員の記録。

## 休暇レコード

ある従業員の1つの日付に対する休暇。物理的には `attendance_records` の1行である。

| 項目 | 物理カラム | 規則 |
| --- | --- | --- |
| 識別子 | `id` | 作成時に採番する。API の操作キーには使わない。 |
| 従業員 | `employee_id` | サーバー設定のデモ従業員 ID。要求では指定しない。 |
| 日付 | `attendance_date` | 必須。過去、当日、将来を許可する。形式は `YYYY-MM-DD`。作成後は変更しない。 |
| 休暇区分 | `status` | 必須。保存値は下表のコードだけ。 |
| メモ | `notes` | 任意。API では最大500文字。空または空白のみはメモなしとして保存する。 |
| 出勤・退勤 | `clock_in_time`, `clock_out_time` | 休暇では空にする。勤務行を休暇へ変えるときは、従業員の確認後だけ空にする。 |
| 作成日時・更新日時 | `created_at`, `updated_at` | 作成時と更新時に記録する。 |

### 休暇区分

| 利用者に示す名称 | 保存するコード |
| --- | --- |
| Sick Leave | `SICK_LEAVE` |
| Personal Leave | `PERSONAL_LEAVE` |
| Business Trip | `BUSINESS_TRIP` |

これ以外の名称やコードは保存しない。勤務を表す `WORK` は休暇区分ではない。

## 制約

- 同じ従業員の同じ日付には、勤怠レコードが1件だけ存在する。休暇もこの制約に従う。
- 休暇として扱えるのは、ステータスが上表の3コードであるレコードだけである。
- 同じ日付に休暇がある追加作成は拒否する。勤務行は、確認後だけ同じ行を休暇へ変え、出勤・退勤時刻を空にする。確認なしでは勤務行を変えない。
- メモが500文字を超える場合は保存しない。
- 日付または休暇区分がない作成・更新は保存しない。

## 状態遷移

1. **不存在**: その日付に休暇コードのレコードがない。勤務のみの日も、休暇の取得・更新・削除では不存在として扱う。勤務日の登録は、確認後にこの行を登録済みへ変える。
2. **登録済み**: 日付、休暇区分、メモを持つ。再取得すると保存時の内容が得られる。
3. **変更済み**: 休暇区分またはメモだけが変わる。日付と従業員は変わらない。
4. **削除済み**: 行を削除し、以後の取得結果に含めない。同じ日付へ改めて作成すれば、新しい休暇として記録できる。

更新と削除は、登録済みの休暇からだけ遷移できる。対象がない操作は成功にせず、レコードを増やさない。
