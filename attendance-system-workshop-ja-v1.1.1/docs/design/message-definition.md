# メッセージ定義書

システムで使用するすべてのメッセージを一元管理します。

## 命名規則

### メッセージID

* **エラーメッセージ**: `ERR{カテゴリ2桁}{連番3桁}` (例: `ERR01001`)
* **成功メッセージ**: `SUCCESS{カテゴリ2桁}{連番3桁}` (例: `SUCCESS01001`)
* **情報メッセージ**: `INFO{カテゴリ2桁}{連番3桁}` (例: `INFO01001`)
* **警告メッセージ**: `WARN{カテゴリ2桁}{連番3桁}` (例: `WARN01001`)
* **カテゴリ番号**: 機能グループごとに割り当て

## カテゴリ一覧

| カテゴリ | カテゴリ名     | 説明                         |
| -------- | -------------- | ---------------------------- |
| 01       | システム       | システム起動・ヘルスチェック |
| 02       | 勤怠管理       | 勤務時間入力・休暇登録       |
| 03       | バリデーション | 入力値検証                   |
| 99       | 共通           | 共通メッセージ               |

## メッセージ一覧

### カテゴリ01: システム

#### REQ-UC001: システム起動

| メッセージID | メッセージ内容                                                       | 説明                     | 関連画面 | 関連要件  |
| ------------ | -------------------------------------------------------------------- | ------------------------ | -------- | --------- |
| INFO01001    | システムを起動しています...                                          | システム起動中の情報表示 | SCR-001  | REQ-UC001 |
| ERR01001     | システムに接続できませんでした。しばらくしてから再度お試しください。 | システム接続エラー       | SCR-001  | REQ-UC001 |
| ERR01002     | システムが一時的に利用できません。                                   | システムメンテナンス中   | -        | REQ-UC001 |

#### REQ-UC002: カレンダー操作

| メッセージID | メッセージ内容                  | 説明                                         | 関連画面 | 関連要件  |
| ------------ | ------------------------------- | -------------------------------------------- | -------- | --------- |
| INFO01003    | カレンダーを読み込んでいます... | カレンダー初期表示時の情報表示（オプション） | SCR-001  | REQ-UC002 |

**備考**: REQ-UC002（カレンダー操作）は、フロントエンド側の状態管理のみで実現されるため、エラーメッセージは発生しません。日付選択や月切り替えは即座に実行され、ユーザーへのフィードバックは視覚的な変更（ハイライト、カレンダー更新）で行われます。

### カテゴリ02: 勤怠管理

#### REQ-UC003: 勤務時間入力

| メッセージID | メッセージ内容                           | 説明                         | 関連画面 | 関連要件  |
| ------------ | ---------------------------------------- | ---------------------------- | -------- | --------- |
| SUCCESS02001 | 勤怠情報が正常に保存されました           | 勤務時間の保存成功           | SCR-002  | REQ-UC003 |
| ERR02001     | 指定した日付の勤怠レコードはありません   | 特定日取得で未登録           | -        | REQ-UC003 |

SCR-002 を開いたときの特定日取得が 404 の場合、ERR02001 は画面に出さない。空欄の初期表示とする。ERR02001 は API 応答のメッセージである。

#### REQ-UC004: 休暇登録

| メッセージID | メッセージ内容                                                                 | 説明                           | 関連画面 | 関連要件  |
| ------------ | ------------------------------------------------------------------------------ | ------------------------------ | -------- | --------- |
| SUCCESS02002 | 休暇を登録しました                                                             | 休暇の新規登録成功             | SCR-003  | REQ-UC004 |
| SUCCESS02003 | 休暇を変更しました                                                             | 休暇の変更成功                 | SCR-003  | REQ-UC004 |
| SUCCESS02004 | 休暇を削除しました                                                             | 休暇の削除成功                 | SCR-003  | REQ-UC004 |
| ERR02002     | 指定した日付の休暇はありません                                                 | 休暇の取得・更新・削除で対象なし | SCR-003  | REQ-UC004 |
| ERR02003     | この日付にはすでに休暇が登録されています。変更または削除を使ってください | 新規登録時に休暇行がある       | SCR-003  | REQ-UC004 |
| ERR02005     | この日付には勤務時間が登録されています。休暇にすると出勤・退勤時刻は削除されます | 確認なしの勤務日登録           | SCR-003  | REQ-UC004 |

SCR-003 を開いたときの `GET /api/leaves/{date}` が 404 の場合、ERR02002 は画面に出さない。空の新規登録状態とする。更新・削除の 404 では ERR02002 を表示し、成功表示は出さない。

## メッセージ詳細定義

### INFO01001: システムを起動しています...

- **メッセージタイプ**: INFO（情報）
- **カテゴリ名**: システム
- **表示条件**: システム起動時、メイン画面のロード中
- **ユーザーの対処方法**: なし（待機）
- **関連画面**: SCR-001（メイン画面）
- **関連要件**: REQ-UC001
- **HTTPステータスコード**: -（フロントエンド表示のみ）

### ERR01001: システムに接続できませんでした。しばらくしてから再度お試しください。

- **メッセージタイプ**: ERROR（エラー）
- **カテゴリ名**: システム
- **表示条件**: システムURLにアクセスしたが、バックエンドAPIに接続できない場合
- **ユーザーの対処方法**: しばらく待ってから再度アクセスする、またはシステム管理者に連絡
- **関連画面**: SCR-001（メイン画面）
- **関連要件**: REQ-UC001
- **HTTPステータスコード**: -（接続エラーのため）

### ERR01002: システムが一時的に利用できません。

- **メッセージタイプ**: ERROR（エラー）
- **カテゴリ名**: システム
- **表示条件**: システムメンテナンス中またはヘルスチェックで「DOWN」が返された場合
- **ユーザーの対処方法**: メンテナンス終了まで待機
- **関連画面**: -
- **関連要件**: REQ-UC001
- **HTTPステータスコード**: 503

### INFO01003: カレンダーを読み込んでいます...

- **メッセージタイプ**: INFO（情報）
- **カテゴリ名**: システム
- **表示条件**: カレンダー初期表示時（オプション）。通常は即座に表示されるため、このメッセージは表示されない
- **ユーザーの対処方法**: なし（待機）
- **関連画面**: SCR-001（メイン画面）
- **関連要件**: REQ-UC002
- **HTTPステータスコード**: -（フロントエンド表示のみ）
- **備考**: REQ-UC002の実装では、カレンダーはフロントエンド側で即座に生成されるため、通常このメッセージは不要。将来的にバックエンドから勤怠データを取得する場合にのみ使用される可能性がある

### ERR99001: 予期しないエラーが発生しました。システム管理者に連絡してください。

- **メッセージタイプ**: ERROR（エラー）
- **カテゴリ名**: 共通
- **表示条件**: 予期しない例外が発生した場合（catch-allエラー）
- **ユーザーの対処方法**: システム管理者に連絡し、エラー発生時刻と操作内容を報告
- **関連画面**: 全画面
- **関連要件**: 全要件
- **HTTPステータスコード**: 500

### ERR99002: ネットワークエラーが発生しました。接続を確認してください。

- **メッセージタイプ**: ERROR（エラー）
- **カテゴリ名**: 共通
- **表示条件**: ネットワーク接続が切断された、またはタイムアウトした場合
- **ユーザーの対処方法**: ネットワーク接続を確認し、再度操作を実行
- **関連画面**: 全画面
- **関連要件**: 全要件
- **HTTPステータスコード**: -（ネットワークエラーのため）

### SUCCESS02001: 勤怠情報が正常に保存されました

- **メッセージタイプ**: SUCCESS（成功）
- **カテゴリ名**: 勤怠管理
- **表示条件**: 勤務時間の検証と保存が成功し、SCR-002 を閉じたあと
- **ユーザーの対処方法**: なし
- **関連画面**: SCR-001（メイン画面）。保存操作の起点は SCR-002
- **関連要件**: REQ-UC003
- **HTTPステータスコード**: 200（API は勤怠レコードを返す。この文言はフロントエンドが表示する）

### ERR02001: 指定した日付の勤怠レコードはありません

- **メッセージタイプ**: ERROR（エラー）
- **カテゴリ名**: 勤怠管理
- **表示条件**: 特定日取得で、従業員と日付の勤怠レコードが存在しない
- **ユーザーの対処方法**: 勤務時間を入力して保存する。SCR-002 の初期表示ではこのメッセージを出さず、時刻欄を空欄にする
- **関連画面**: -
- **関連要件**: REQ-UC003
- **HTTPステータスコード**: 404

### ERR03001: 出勤時刻は退勤時刻より前である必要があります

- **メッセージタイプ**: ERROR（エラー）
- **カテゴリ名**: バリデーション
- **表示条件**: 出勤時刻と退勤時刻が同刻、または出勤時刻が退勤時刻以降である
- **ユーザーの対処方法**: 出勤時刻が退勤時刻より前になるよう修正して再保存する
- **関連画面**: SCR-002（勤務時間入力フォーム）
- **関連要件**: REQ-UC003
- **HTTPステータスコード**: 400
- **備考**: 検証失敗時は勤怠レコードを保存しない。ダイアログは閉じない

### ERR03002: 有効な時刻形式で入力してください

- **メッセージタイプ**: ERROR（エラー）
- **カテゴリ名**: バリデーション
- **表示条件**: 出勤時刻または退勤時刻が `HH:MM`（00:00〜23:59）でない
- **ユーザーの対処方法**: 24 時間表記の時と分で入力し直す
- **関連画面**: SCR-002（勤務時間入力フォーム）
- **関連要件**: REQ-UC003
- **HTTPステータスコード**: 400
- **備考**: 検証失敗時は勤怠レコードを保存しない

### SUCCESS02002: 休暇を登録しました

- **メッセージタイプ**: SUCCESS（成功）
- **カテゴリ名**: 勤怠管理
- **表示条件**: 休暇の検証と新規登録が成功し、SCR-003 を閉じたあと
- **ユーザーの対処方法**: なし
- **関連画面**: SCR-001（メイン画面）。操作の起点は SCR-003
- **関連要件**: REQ-UC004
- **HTTPステータスコード**: 201（API は休暇レコードを返す。この文言はフロントエンドが表示する）

### SUCCESS02003: 休暇を変更しました

- **メッセージタイプ**: SUCCESS（成功）
- **カテゴリ名**: 勤怠管理
- **表示条件**: 既存休暇の変更が成功し、SCR-003 を閉じたあと
- **ユーザーの対処方法**: なし
- **関連画面**: SCR-001（メイン画面）。操作の起点は SCR-003
- **関連要件**: REQ-UC004
- **HTTPステータスコード**: 200

### SUCCESS02004: 休暇を削除しました

- **メッセージタイプ**: SUCCESS（成功）
- **カテゴリ名**: 勤怠管理
- **表示条件**: 既存休暇の削除が成功し、SCR-003 を閉じたあと
- **ユーザーの対処方法**: なし
- **関連画面**: SCR-001（メイン画面）。操作の起点は SCR-003
- **関連要件**: REQ-UC004
- **HTTPステータスコード**: 204（API はボディを返さない。この文言はフロントエンドが表示する）

### ERR02002: 指定した日付の休暇はありません

- **メッセージタイプ**: ERROR（エラー）
- **カテゴリ名**: 勤怠管理
- **表示条件**: 指定日に休暇ステータスの行がない。勤務のみの日も含む
- **ユーザーの対処方法**: 新規登録する。SCR-003 の初期表示ではこのメッセージを出さず、区分とメモを空欄にする。更新・削除では成功表示を出さない
- **関連画面**: SCR-003（休暇登録フォーム）
- **関連要件**: REQ-UC004
- **HTTPステータスコード**: 404

### ERR02003: この日付にはすでに休暇が登録されています。変更または削除を使ってください

- **メッセージタイプ**: ERROR（エラー）
- **カテゴリ名**: 勤怠管理
- **表示条件**: 新規登録しようとした日付に、同じ従業員の休暇行が既にある
- **ユーザーの対処方法**: 変更または削除を使う。`confirmReplaceWork` では休暇行を上書きしない
- **関連画面**: SCR-003（休暇登録フォーム）
- **関連要件**: REQ-UC004
- **HTTPステータスコード**: 409
- **備考**: 既存の休暇行は変更しない

### ERR02005: この日付には勤務時間が登録されています。休暇にすると出勤・退勤時刻は削除されます

- **メッセージタイプ**: ERROR（エラー）
- **カテゴリ名**: 勤怠管理
- **表示条件**: 新規登録しようとした日付に勤務行があり、`confirmReplaceWork` が true でない
- **ユーザーの対処方法**: 時刻を削除して休暇にしてよい場合だけ確認し、`confirmReplaceWork: true` で再送する。確認しない場合は何もしない
- **関連画面**: SCR-003（休暇登録フォーム）
- **関連要件**: REQ-UC004
- **HTTPステータスコード**: 409
- **備考**: この応答では出勤・退勤時刻を変えない。確認後の再送が成功したときは SUCCESS02002 を表示する

### ERR03004: 休暇日を指定してください

- **メッセージタイプ**: ERROR（エラー）
- **カテゴリ名**: バリデーション
- **表示条件**: 休暇日が未指定、または `YYYY-MM-DD` の有効な日付でない
- **ユーザーの対処方法**: SCR-001 で日付を選び直す
- **関連画面**: SCR-003（休暇登録フォーム）
- **関連要件**: REQ-UC004
- **HTTPステータスコード**: 400
- **備考**: 画面で検出できる場合は API を呼ばない。保存しない

### ERR03005: 休暇区分を選択してください

- **メッセージタイプ**: ERROR（エラー）
- **カテゴリ名**: バリデーション
- **表示条件**: 休暇区分が未選択である
- **ユーザーの対処方法**: Sick Leave、Personal Leave、Business Trip のいずれかを選んで再保存する
- **関連画面**: SCR-003（休暇登録フォーム）
- **関連要件**: REQ-UC004
- **HTTPステータスコード**: 400
- **備考**: 画面で検出できる場合は API を呼ばない。保存しない

### ERR03006: 対応する休暇区分を選択してください

- **メッセージタイプ**: ERROR（エラー）
- **カテゴリ名**: バリデーション
- **表示条件**: 休暇区分が Sick Leave、Personal Leave、Business Trip 以外である
- **ユーザーの対処方法**: 表示されている3区分から選び直す
- **関連画面**: SCR-003（休暇登録フォーム）
- **関連要件**: REQ-UC004
- **HTTPステータスコード**: 400
- **備考**: 行は追加も更新もしない

### ERR03007: メモは500文字以内で入力してください

- **メッセージタイプ**: ERROR（エラー）
- **カテゴリ名**: バリデーション
- **表示条件**: メモが501文字以上である
- **ユーザーの対処方法**: 500文字以内に修正して再保存する
- **関連画面**: SCR-003（休暇登録フォーム）
- **関連要件**: REQ-UC004
- **HTTPステータスコード**: 400
- **備考**: 画面で検出できる場合は API を呼ばない。空白のみはメモなしとして保存し、このエラーにはしない

### ERR03008: 開始日と終了日は両方指定してください

- **メッセージタイプ**: ERROR（エラー）
- **カテゴリ名**: バリデーション
- **表示条件**: `GET /api/leaves` で `from` と `to` の片方だけが指定された、または日付が不正である
- **ユーザーの対処方法**: 期間を使う場合は開始日と終了日を両方指定する。SCR-003 はこの API を使わない
- **関連画面**: -
- **関連要件**: REQ-UC004
- **HTTPステータスコード**: 400

### ERR03003: 出勤時刻と退勤時刻を入力してください

- **メッセージタイプ**: ERROR（エラー）
- **カテゴリ名**: バリデーション
- **表示条件**: 出勤時刻または退勤時刻が未入力である
- **ユーザーの対処方法**: 両方の時刻を入力して再保存する
- **関連画面**: SCR-002（勤務時間入力フォーム）
- **関連要件**: REQ-UC003
- **HTTPステータスコード**: 400
- **備考**: 検証失敗時は勤怠レコードを保存しない
